# 同步发知乎、掘金

博客是首发地，知乎、掘金是转发渠道。不要把博客里的 `.md` 原文件直接贴过去：里面有站内相对路径（图片在平台上显示不出来）、kramdown 专用写法（`{: .dark }` 等会原样露出来），表格也容易排乱。用导出脚本生成一份平台专用的副本。

## 谁来发

- 用的是**仓主自己的**知乎、掘金账号。发不发、发哪篇、什么时候发，由仓主决定。
- muse 经仓主同意可以代为操作；Claude 不登录仓主的任何平台账号，只负责导出文件和检查。
- 转发的文字和博客一致，不为平台改写、删减或"优化标题"。要改，先问仓主。

## 流程

1. **确认博客上这篇是好的**：先跑 `lint_markdown.py`，有 E 级错误先按 `publish-post.md`「排版检查」修好。源文件坏了，导出也是坏的（脚本会拒绝导出）。
2. **导出**：
   ```bash
   python3 .claude/skills/lingquan-blog/scripts/export_post.py _posts/<文章>.md --platform juejin
   python3 .claude/skills/lingquan-blog/scripts/export_post.py _posts/<文章>.md --platform zhihu [--tables image]
   ```
   得到 `_export/<文章>/juejin.md`、`zhihu.md`（`_export/` 不提交）。脚本会打印标题、标签、封面地址和原文链接。
3. **按平台发**（下面写的是 2026-11 的做法，平台界面会变，以实际为准；发现不一样就更新本节）：
   - **掘金**：编辑器本身就是 Markdown（GFM），把 `juejin.md` 的内容整篇粘进去。表格、公式、代码块都能直接显示。外链图片如果没显示出来，在编辑器里手动上传那几张。
   - **知乎**：在写文章页用「导入文档」导入 `zhihu.md`，不要复制粘贴（粘贴会丢格式）。导入后逐张检查表格和公式。表格错位、列被压得很窄时，改用 `--tables image` 重新导出：表格会画成白底图片（`table-1.png`…），在知乎编辑器里逐张上传替换，图下保留了一行"文字版见博客原文"的链接。
4. **发之前对照博客页面看一遍**：表格数、图片数、公式数和博客一致；代码块有语言高亮；文末有原文链接。
5. **记录**：在 `log.md` 记一句"《标题》已同步到知乎/掘金"，附上平台文章链接（公开链接，可以写）。

## 表格写法建议（对博客和平台都友好）

- 表格前后都留空行（这是本站 kramdown 的硬要求，也让各平台导入更稳）。
- 列数尽量不超过 5 列，单元格里少放长句；数字表格比文字表格更适合转发。
- 表格前一行用 `#### 表N 标题` 这种小标题时，标题和表格之间也要空一行。
- 单元格里需要竖线时写 `\|`。

## 导出脚本做了什么

见 `scripts/export_post.py` 开头的说明。要点：站内路径改成 `https://lingquan11.github.io/...`；深色版图片删掉、只留浅色版（平台都是白底）；表格分隔行统一为 `|---|`，表格和公式块前后补空行；独占一段的 `$$公式$$` 改成三行写法，段落里的改成 `$公式$`；文末加原文链接。只改导出副本，文字一字不动，博客原文件不受影响。
